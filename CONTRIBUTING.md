## Repository layout

### Code and delivery

| What | Where |
|------|-------|
| Cargo workspace: `tldr-core`, `tldr-cli`, `tldr-daemon`, `tldr-mcp` | `Cargo.toml`, `crates/` |
| Upstream build targets: `build`, `test`, `lint`, `fmt`, `check` | `MakefileTLDR` |
| Image build | `Dockerfile`, `.dockerignore` |
| Image checks | `scripts/docker-smoke.sh`, `scripts/docker-readme-check.sh`, `scripts/docker-smoke-selftest.sh` |
| Image pipeline | `.github/workflows/docker.yml` |
| Binary release pipeline, generated by cargo-dist | `.github/workflows/release.yml`, `dist-workspace.toml` |

| What | Where |
|------|-------|

## Docker image

The image is built in two stages: `rust` builds `tldr` and `tldr-mcp`, `debian-slim` runs them as a
non-root user with `git` installed. The Rust version is pinned by `ARG RUST_VERSION` in `Dockerfile`
and is raised by a separate change. The build context is limited to `Cargo.toml`, `Cargo.lock` and
`crates/` by `.dockerignore`, so edits to documents do not invalidate the build cache.

`docker.yml` builds, checks and publishes `ghcr.io/united-software-platform/tldr-code`:

| Event | Architectures | Published tags |
|-------|---------------|----------------|
| Pull request | `amd64` | none — build and checks only |
| Push to a `TLDR-*` branch | `amd64`, `arm64` | `dev-<short sha>` |
| Tag `vX.Y.Z` | `amd64`, `arm64` | `X.Y.Z`, `X.Y`, `latest` |
| Tag `vX.Y.Z-<suffix>` | `amd64`, `arm64` | `X.Y.Z-<suffix>` only |

Each architecture passes the three image checks before it is pushed. An image of a working branch is
tried before a release by its tag:

```bash
docker pull ghcr.io/united-software-platform/tldr-code:dev-<short sha>
```

The image contract is the spec [`openspec/specs/docker-image/spec.md`](./openspec/specs/docker-image/spec.md).

## Release

A release starts with the tag `vX.Y.Z`. The tag must equal `[workspace.package] version` in `Cargo.toml`:
the `check-version` job of `docker.yml` fails otherwise, and no image is published. The same tag
triggers `release.yml`, which builds binary archives with cargo-dist. `release.yml` is regenerated
by cargo-dist and is not edited by hand; image changes go to `docker.yml`.

## Badges

The badge block stands in [`README.md`](./README.md) between the title and the purpose. The version badge
is dynamic: the badge service reads the latest tag, and `README.md` holds no copy of the number.

| Badge | Value source | Mode | Link target |
|-------|--------------|------|-------------|
| Version | git tags `vX.Y.Z` of the repository, highest by semver (shields `github/v/tag`) | dynamic | GHCR package `tldr-code` |
| License | static value `AGPL-3.0`, matching `LICENSE` | static | `./LICENSE` |
| Docker image | status of `.github/workflows/docker.yml` (shields `github/actions/workflow/status`) | dynamic | runs of the workflow in Actions |
| Platforms | static value `linux/amd64 \| linux/arm64`, matching the build matrix of `docker.yml` | static | GHCR package `tldr-code` |

Limits of the block:

- **the repository must be readable anonymously** — the badge service reads tags and workflow status without authentication;
- **renaming `docker.yml` breaks the Docker image badge silently** — after renaming, the badge is checked by eye;
- **a new architecture in the build matrix** is added to the Platforms badge by the same change.

## Checks

Checks run before changes are pushed, each with its own command, from the repository root:

```bash
make -f MakefileTLDR check                          # cargo fmt --check, clippy -D warnings, unit tests
docker build -t tldr-code:smoke .                   # local image for the three checks below
sh scripts/docker-smoke.sh tldr-code:smoke          # delivery contract of the image
sh scripts/docker-readme-check.sh tldr-code:smoke   # Docker examples of README.md and docs/use-cases.md
sh scripts/docker-smoke-selftest.sh tldr-code:smoke # the smoke test catches a broken image
sh tools/make-lint/check.sh                         # target size of Makefile
```

The image checks need `docker` and `jq` on `PATH`. Their exit codes:

| Code | Meaning | What to do |
|------|---------|------------|
| `0` | Every check passed | The image is ready to be pushed |
| `1` | At least one check failed; its line starts with `FAIL -`. For `docker-smoke-selftest.sh` it means the smoke test did not catch the broken image | The image or the documented example is fixed, and the check is rerun |
| `2` | Invocation or environment error: no image argument, `docker` or `jq` missing, image not built locally | The image is built with `docker build`, and its name is passed to the script |

`docker-readme-check.sh` does not parse the documents: it keeps its own copy of each Docker example
of `README.md` and `docs/use-cases.md` and runs it. An example it runs and the script are changed
in the same commit, and they differ only in the image name.
