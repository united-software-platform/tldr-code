# Proposal: add-docker-image-delivery

Обоснование и состав изменения: поставка `tldr-cli` как Docker-образа, который запускается в любом
проекте без установки инструмента.

## Why

Сейчас `tldr` попадает в систему только через `cargo install tldr-cli`: нужен установленный
Rust-тулчейн, сборка из исходников и бинарь в `PATH` каждой машины. Это закрывает путь в проекты
и окружения, где Rust нет, — CI чужих репозиториев, контейнеры агентов, машины без прав на установку.
Готовый образ снимает это ограничение: `docker run` с проектом, смонтированным только для чтения,
даёт те же команды без установки чего-либо.

## What Changes

- Добавляется многоэтапный `Dockerfile` в корне репозитория и `.dockerignore`: сборка бинарей `tldr`
  и `tldr-mcp` из исходников и минимальный образ выполнения с `git`.
- Образ публикуется в реестре контейнеров GitHub (GitHub Container Registry, GHCR) как
  `ghcr.io/united-software-platform/tldr-code` для архитектур `linux/amd64` и `linux/arm64`;
  выпуск `vX.Y.Z` даёт теги `X.Y.Z`, `X.Y`, `latest`, пре-релиз — только собственный тег.
- Добавляется отдельный workflow непрерывной интеграции (Continuous Integration, CI)
  `.github/workflows/docker.yml`: сборка и проверка образа на запрос слияния (Pull Request, PR), сборка, проверка и публикация
  на тег выпуска, проверочный тег `dev-<короткий sha>` на push в рабочую ветку `TLDR-*`.
  Существующий `release.yml` (cargo-dist) не меняется.
- Добавляется скрипт `scripts/docker-smoke.sh` — дымовая проверка образа: проект смонтирован
  только для чтения, контейнер запущен под произвольным идентификатором пользователя (User Identifier, UID). Проверка — блокирующий шаг перед публикацией.
- В `README.md` в раздел `Installation` добавляется подраздел `### Docker (no install)`: команда
  запуска, однострочная shell-функция, подключение сервера протокола контекста модели (Model Context Protocol, MCP), ограничения образа.
- Код crate'ов не меняется: изменение — упаковка и поставка.

Вне объёма: семантический поиск (feature `semantic`), daemon, сторонние линтеры в образе, правки
Rust-кода, цели `Makefile`/`MakefileTLDR`.

## Capabilities

### New Capabilities

- `docker-image`: поставка `tldr` как контейнерного образа — контракт запуска (точка входа,
  рабочий каталог, монтирование проекта только для чтения, произвольный UID, каналы вывода),
  MCP-сервер в образе, публикуемые теги и архитектуры, метаданные образа, проверка перед публикацией
  и документированные ограничения.

### Modified Capabilities

Нет: каталог `openspec/specs/` пуст, существующих возможностей изменение не затрагивает.

## Impact

- **Новые файлы**: `Dockerfile`, `.dockerignore`, `.github/workflows/docker.yml`,
  `scripts/docker-smoke.sh`.
- **Изменяемые файлы**: `README.md` — новый подраздел установки.
- **Внешние системы**: GHCR организации `united-software-platform`; workflow требует права
  `packages: write`. После первой публикации администратор организации вручную делает пакет
  публичным — без этого `docker pull` требует логина.
- **Зависимости сборки**: образы `rust:<закреплённая stable>-trixie` и `debian:trixie-slim`;
  раннеры GitHub `ubuntu-24.04` и `ubuntu-24.04-arm`.
- **Совместимость**: канал `cargo install tldr-cli` сохраняется, версия образа совпадает с версией crate.
